I try Python 3.13 with the nightly orck 2.10 and see if it works better with the VAE decode issue

SCRIPT

```cmd
git init
git remote add origin https://github.com/comfyanonymous/ComfyUI.git
git fetch
git checkout -t origin/master

uv venv .venv --python 3.13

call .venv\Scripts\activate.bat

uv pip install --index-url https://rocm.nightlies.amd.com/v2/gfx110X-dgpu/ "rocm[libraries,devel]"

uv pip install --index-url https://rocm.nightlies.amd.com/v2/gfx110X-dgpu/ --pre torch torchaudio torchvision

uv pip install -r requirements.txt --link-mode=copy

cd custom_nodes

git clone https://github.com/Comfy-Org/ComfyUI-Manager.git

git clone https://github.com/M1kep/ComfyLiterals

git clone https://github.com/fuselayer/comfyui-minimal-workflow-image

cd ..

uv run main.py --use-pytorch-cross-attention
```

# Final Workflow

## 7900 XTX Windows ROCm

Use ```--use-pytorch-cross-attention``` when launcheing comfyUI. Note that reload after installing nodes might not use the flag, so close and relaunch manually with the flag.

Use [city96 GGUF loaders](https://github.com/city96/ComfyUI-GGUF), as the 7900XTX does support hardware acceleration for INT8. I had no luck with FP8 that defaults to BF16 instead.

Use GGUF loaders for both the CLIP and ZIT model, Q8 seems to work really well.

When changing the prompt, CLIP is re executed, while keeping the prompt the same will just run the diffusion model. This can cause severe slowdowns if both don't fill RAM, hence why lowering quant really speed things up.

First execution: 20.96 s

Second Execution: 10.6 s
